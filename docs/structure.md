# プログラムの構成と仕組み

この文書では、アプリがどのファイルで構成されていて、それぞれの機能がどのように動いているかを説明します。使い方だけを知りたい場合は、読まなくても問題ありません。

## 使っているライブラリとツール

描画には libGDX 1.10.0 を使っています。libGDX は Android などで 2D や 3D の描画を行うためのゲーム用ライブラリで、アプリをライブ壁紙として動かすための仕組みも含んでいます。

Spine の素材の読み込みと描画には、spine-libgdx 3.8.99.1 を使っています。これは Spine の開発元が提供している、libGDX 向けの読み込み処理です。Spine の素材は、書き出したエディターと同じバージョンの読み込み処理でないと正しく読めません。最初に使ったテキサスの素材が Spine 3.8.99 で書き出されていたので、それに合わせてこのバージョンを選びました。libGDX のバージョンは、spine-libgdx 3.8.99.1 が作られたときに使われていた 1.10.0 に揃えています。

ビルドには Gradle 8.14.3 と Android Gradle Plugin 8.11.0 を使い、プログラムは Java で書いています。対応する Android のバージョンは 7.0（API レベル 24）以上です。

## ファイルの配置

```
android_live2d/
├─ app/
│  ├─ build.gradle                 アプリのビルド設定（ライブラリのバージョンなど）
│  ├─ libs/                        ビルドのときに自動で作られる libGDX の部品
│  └─ src/main/
│     ├─ AndroidManifest.xml       アプリと壁紙を Android に登録する設定
│     ├─ assets/
│     │  ├─ background/            背景画像
│     │  └─ character/             キャラクターの Spine 素材
│     ├─ java/moe/coiluck/spinewallpaper/
│     │  ├─ CharacterScene.java    描画、アニメーション、タップの判定
│     │  ├─ LiveWallpaper.java     ライブ壁紙として表示するためのクラス
│     │  └─ MainActivity.java      アプリを開いたときに、壁紙の設定画面を開く
│     └─ res/xml/wallpaper.xml     ライブ壁紙であることを示す設定
├─ doc/                            このドキュメント

```

## 3 つのクラスの役割

表示の中身は、すべて `CharacterScene` が受け持っています。素材の読み込み、背景とキャラクターの描画、アニメーションの切り替え、タップの判定がこのクラスにまとまっています。

`LiveWallpaper` は、`CharacterScene` をホーム画面の壁紙として表示するためのクラスです。Android に壁紙として登録されているのはこのクラスで、ホームアプリから届くタップの通知もここで受け取り、`CharacterScene` に渡しています。

`MainActivity` は、アプリ一覧から「Spine Wallpaper」を開いたときに動くクラスです。Android が用意しているライブ壁紙の設定画面を、このアプリの壁紙を選んだ状態で開き、自分自身はすぐに閉じます。そのため、アプリ独自の画面は表示されません。機種によってこの設定画面を直接開けない場合は、代わりにライブ壁紙の一覧を開きます。

## 素材の読み込み

`CharacterScene` は起動したときに、`assets/background/` と `assets/character/` にあるファイルを調べ、ファイル名の末尾で種類を見分けます。背景は `.png`、`.jpg`、`.jpeg` のいずれかで終わるファイルです。キャラクターは、`.atlas` で終わるファイルを atlas ファイル、`.skel` または `.json` で終わるファイルを骨格データとして扱います。どの場合も、さらに後ろに `.txt` が付いていて構いません。

ダウンロードした atlas ファイルの中では、画像のファイル名に含まれる `#` が `%23` と書かれていることがあります。これは、URL で使えない文字を `%` と数字で書き表す方式によるものです。書かれた名前の画像が見つからないときは、この表記を元の文字に戻したうえで、画像を探し直しています。

アニメーションは、`Idle`、`Interact`、`Special` という名前で探します。アークナイツの動的立ち絵は、この 3 つの名前を使っています。`Interact` や `Special` がない素材では、それぞれタップへの反応とときどきの再生を行いません。`Idle` がない素材では、アプリが起動できません。

## 描画

画面は 1 秒間に何十回も描き直されます。そのたびに、まず背景画像を画面全体を覆う大きさで描き、その上にキャラクターを描きます。

アークナイツの素材の画像は、各画素の色の値に、あらかじめ透明度を掛けた形式で保存されています。この形式を premultiplied alpha と呼びます。描画する側がこの形式を前提にしないと、半透明の縁が黒ずんで見えます。そのため、描画の設定で premultiplied alpha を使うことを指定しています。

キャラクターの大きさの基準は、起動したときに測ります。待機アニメーションの最初の姿勢で、キャラクター全体を囲む長方形を求め、その長方形が画面にちょうど収まる倍率を 1.0 としています。

## タップへの反応

壁紙に届くタップには、2 つの経路があります。1 つは、ホーム画面のアイコンなどがない場所をタップしたときに、ホームアプリから壁紙へ送られる通知です。もう 1 つは、画面へのタッチ操作そのものです。ホームアプリによって、どちらの経路で届くかが異なるので、両方を受け取るようにしています。

タッチ操作のほうは、指を動かさずに短く触れた場合だけをタップとして扱います。そのため、ホーム画面をスワイプしてページを切り替えても、アニメーションは変わりません。

1 回のタップが両方の経路から届く場合があるので、Interact の再生中に届いたタップは無視しています。無視しないと、同じタップで Interact が最初から再生し直されてしまいます。

タップした位置がキャラクターの上かどうかは、Spine の描画の仕組みを使って判定しています。Spine のキャラクターは、髪や腕などの部品の画像を、三角形を並べた網目や四角形に貼り付けて描いています。タップした位置が、そのときに表示されている部品の三角形か四角形のどれかの内側にあれば、キャラクターに触れたと判定します。非表示の部品と、完全に透明にされている部品は判定から除きます。

この方法では、キャラクターを囲む長方形で判定するよりも、実際の形に近い範囲だけが反応します。ただし、部品の画像の透明な部分も判定に含まれるので、見た目の輪郭より少し外側まで反応することがあります。また、人物だけでなく、素材に含まれる足場や小物の上をタップしても反応します。

## Special の再生

画面を描き直すたびに、待機アニメーションを再生している間だけ、Special までの残り時間を減らしていきます。残り時間がなくなると Special を一度再生し、終わると待機に戻ります。

## 電池の消費を抑える仕組み

libGDX のライブ壁紙の仕組みは、壁紙がほかのアプリの画面に隠れると描画の繰り返しを一時停止し、再び見えるようになると再開します。このアプリはこの仕組みをそのまま使っています。

また、libGDX は初期設定では加速度センサーとコンパスの値を読み取り続けますが、このアプリではどちらも使わないので無効にしています。

どちらも仕組みのうえでの対策であり、実際の電池の消費量は計測していません。
